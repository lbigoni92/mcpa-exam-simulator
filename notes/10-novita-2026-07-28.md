# Novità della spec 2026-07-28 rispetto alla 2025-11-25

> Fonte primaria: `sources/spec-2026-07-28/changelog.md`, `deprecated.md`, blog `sources/blog/2026-07-28-spec-ga/index.md`. SEP originali in `sources/seps/`.
> Regola di studio: dove tutorial/blog più vecchi contraddicono questa tabella, **vale la 2026-07-28**.

## 1. Major changes
| # | Cambiamento | SEP | Cosa ricordare |
|---|---|---|---|
| 1 | **Niente sessioni di protocollo**, via `Mcp-Session-Id` | 2567 | le liste non variano per connessione; stato cross-call con **handle espliciti** passati come argomenti dei tool |
| 2 | **Protocollo stateless**: via `initialize` / `notifications/initialized` | 2575 | `_meta` di ogni richiesta: `protocolVersion` + `clientCapabilities` (obbligatori), `clientInfo` (SHOULD); result: `serverInfo` (SHOULD); mismatch → `UnsupportedProtocolVersionError` |
| 3 | **`server/discover`** | 2575 | il server MUST implementarlo; il client MAY chiamarlo (selezione versione anticipata, probe su stdio) |
| 4 | **`subscriptions/listen`** sostituisce GET endpoint e `resources/subscribe`/`unsubscribe` | 2575 | filtro opt-in (`toolsListChanged`, `promptsListChanged`, `resourcesListChanged`, `resourceSubscriptions`), ack `notifications/subscriptions/acknowledged`, `subscriptionId` |
| 5 | Rimossi **`ping`**, **`logging/setLevel`**, **`notifications/roots/list_changed`** | 2575 | log level per richiesta con `io.modelcontextprotocol/logLevel`; senza → niente `notifications/message` |
| 6 | **Tasks** escono dal core → estensione `io.modelcontextprotocol/tasks` | 2663 | polling `tasks/get`, nuovo `tasks/update`, rimossi `tasks/result` e `tasks/list`, task handle anche non richiesti |
| 7 | **MRTR** sostituisce le richieste server→client | 2322 | `InputRequiredResult` (`inputRequests`, `requestState`) → retry con `inputResponses`; solo su `tools/call`, `resources/read`, `prompts/get` |
| 8 | **`resultType`** obbligatorio | 2322 | `"complete"` / `"input_required"`; assente ⇒ `complete` |
| 9 | Via **resumability SSE** (`Last-Event-ID`, event ID) | 2575 | stream rotto ⇒ richiesta persa ⇒ ri-emettere con nuovo id |

## 3. Deprecated (restano funzionanti, earliest removal: prima revisione ≥ 2027-07-28)
| Feature | Migrazione |
|---|---|
| **Roots** (SEP-2577) | directory/file via parametri dei tool, URI di resource o configurazione del server |
| **Sampling** (SEP-2577) | integrazione diretta con le API dei provider LLM |
| **Logging** (SEP-2577) | `stderr` (stdio), **OpenTelemetry** |
| **Dynamic Client Registration** (PR #2858) | **Client ID Metadata Documents** |
| `includeContext: "thisServer"/"allServers"` (soft-deprecated dal 2025-11-25) | omettere o `"none"`; rimozione non oltre quella di Sampling |
| **HTTP+SSE transport** (deprecato dal 2025-03-26) | Streamable HTTP; rimozione 3 mesi dopo che SEP-2596 diventa Final |

## 4. Governance e processo
- **Feature lifecycle and deprecation policy** (SEP-2596): stati Active / Deprecated / Removed, finestra minima di 12 mesi, registry delle feature deprecate.
- **Workflow SEP basato su PR** (SEP-1850): file markdown in `seps/`, numero = numero della PR, sponsor, stati tramite label.
- Schema: `minimum`/`maximum`/`default` ora `number` (non solo integer) in `schema.json`.

## 5. Cosa è sparito (lista per le domande "quale di questi NON esiste più?")
`initialize`, `notifications/initialized`, `ping`, `logging/setLevel`, `resources/subscribe`, `resources/unsubscribe`, `notifications/roots/list_changed`, `notifications/elicitation/complete`, `elicitationId`, header `Mcp-Session-Id`, HTTP `GET` e `DELETE` sull'endpoint MCP, `Last-Event-ID`/resumability, richieste JSON-RPC server→client, `tasks/result`, `tasks/list` (e tasks nel core), codici `-32002` e `-32042` (non più emessi).

## 6. Cosa è nuovo (lista per "quale di questi è stato introdotto nella 2026-07-28?")
`server/discover`, `subscriptions/listen`, `notifications/subscriptions/acknowledged`, `InputRequiredResult`, `inputRequests`/`inputResponses`/`requestState`, `resultType`, `_meta` `io.modelcontextprotocol/{protocolVersion, clientInfo, clientCapabilities, logLevel, serverInfo, subscriptionId}`, header `Mcp-Method`, `Mcp-Name`, `Mcp-Param-*`, `x-mcp-header`, `ttlMs`, `cacheScope`, errori `-32020`/`-32021`/`-32022`, `capabilities.extensions`, `traceparent`/`tracestate`/`baggage`, validazione `iss` (RFC 9207), `application_type` obbligatorio, deprecation registry.

## 7. Novità della 2025-11-25 (ancora valide, spesso confuse con la 2026-07-28)
OIDC Discovery 1.0 · icons · step-up scope via `WWW-Authenticate` (SEP-835) · linee guida sui nomi dei tool (SEP-986) · enum elicitation standardizzati (SEP-1330) · **URL mode elicitation** (SEP-1036) · **tools nel sampling** (`tools`, `toolChoice`, SEP-1577) · **CIMD** (SEP-991) · tasks sperimentali (SEP-1686, poi spostati in estensione) · `description` in `Implementation` · `Origin` invalido → 403 · validazione input come Tool Execution Error (SEP-1303) · PRM discovery allineata a RFC 9728 con fallback well-known (SEP-985) · default nelle elicitation (SEP-1034) · JSON Schema 2020-12 default (SEP-1613) · governance (SEP-932, 994, 1302) · SDK tiers (SEP-1730).
